# i18n

Shipeasy i18n is **rendered in the browser** by the client SDK's `t()`. There is
**no server-side `t()` / label-render API** in this PHP SDK — its i18n surface is
the **SSR bootstrap**: it emits the loader `<script>` tag so the browser fetches
and renders translations on first paint.

Both helpers are package-level functions backed by the configured SDK, so call
`Shipeasy\configure()` at startup first — see [Installation](installation.md).

## What the PHP SDK provides

### `Shipeasy\i18nScriptTag($clientKey = null, $profile = null, $opts = [])`

Returns the i18n loader `<script>` tag. The loader fetches translations for the
profile using the **PUBLIC client key** (safe to embed in HTML) — never the
server key. **Every argument is optional**: the key, profile and CDN origin come
from `configure()`, so the normal call carries no arguments:

```php
use function Shipeasy\i18nScriptTag;

// In your document <head>:
$head = i18nScriptTag();
```

Pass an argument only to override the configured value for that one tag —
`i18nScriptTag($clientKey, '{{PROFILE}}', ['baseUrl' => ...])`. Set the defaults
once, at configure time:

```php
Shipeasy\configure($_ENV['SHIPEASY_SERVER_KEY'], null, [
    'clientKey' => $_ENV['SHIPEASY_CLIENT_KEY'],   // PUBLIC key, for the tags
    'projectId' => $_ENV['SHIPEASY_PROJECT_ID'],   // for the devtools tag
    'profile'   => '{{PROFILE}}',
]);
```

A tag still renders when a value is missing (the browser bundle reports what it
needs), but the SDK logs a warning naming the option to fill in — once per
option, not once per render.

### `Shipeasy\devtoolsScriptTag($projectId = null, $opts = [])`

Returns the devtools overlay `<script>` tag — the hosted `se-devtools.js`
bundle, nothing to install. It reads the project id and public client key off
the tag, and opens with **Shift+Alt+S** or on any page loaded with `?se=1`. It is
`defer`red by default: a developer tool never belongs on the critical rendering
path. Its arguments are optional the same way (`$opts`: `'clientKey'`,
`'baseUrl'`, `'defer'`).

```php
$head .= Shipeasy\devtoolsScriptTag();
```

Adding it unconditionally is fine: the overlay only opens for someone with a
signed-in Shipeasy session, so on a page where nobody has authenticated it
renders nothing and says nothing. Gating it on your own staff or environment
check is **optional** — worth it only if you'd rather the bundle not load for
end users at all:

```php
$head .= $user->isStaff() ? Shipeasy\devtoolsScriptTag() : '';
```

### `Shipeasy\bootstrapScriptTag($user = [], $opts = [])`

Emits the request's evaluated flags as a declarative `<script>` tag (no key) so
the browser SDK has flags + the `__se_anon_id` cookie on first paint, bucketing
identically to the server. Pair it with the i18n tag:

```php
use function Shipeasy\bootstrapScriptTag;
use function Shipeasy\i18nScriptTag;

$user = ['user_id' => 'u_123'];

$head = bootstrapScriptTag($user, ['anonId' => $anonId])
      . i18nScriptTag();
```

`$opts` for `bootstrapScriptTag` also accepts `'i18nProfile'` and `'baseUrl'`;
both default to the `profile` / `cdnBaseUrl` passed to `configure()`, and `$user`
itself is optional (no user ⇒ an anonymous request).

**Identity coherence (no anon→identified flip).** When `$user` carries
identified traits (anything beyond `anonymous_id`), the tag also emits them as
`data-user` (JSON, minus `anonymous_id`). The browser SDK adopts that identity on
first paint, so a PHP-backend + JS-frontend app renders as the *same*, already
identified user the server bucketed — there is no flash of anonymous state that
then flips to identified. A purely anonymous request emits no `data-user` (no PII
on the tag). See `experiment-platform/18-identity-bucketing.md`.

## The cross-SDK story

1. **Server (this SDK):** render `i18nScriptTag()` (+ `bootstrapScriptTag()`) into
   the `<head>` with the **public client key** and the `{{PROFILE}}` profile.
2. **Browser (`@shipeasy/sdk/client`):** the loader hydrates translations; your
   markup calls the **client** SDK's `t("key")` to render localized text.

Translations themselves are authored and published in the Shipeasy dashboard /
CLI / MCP under the `{{PROFILE}}` profile. The PHP SDK does not author, fetch, or
render label strings itself — it only wires the loader.
